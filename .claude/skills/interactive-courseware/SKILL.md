# 互动课件制作（经验沉淀）

这份技能来自与一位初中化学老师的长期合作：已交付 7 套课件，经历了几十轮截图反馈。它把老师的偏好、被纠正过的错误和技术经验沉淀下来，目标是让下一套课件一次做到位。

已完成的课件都在仓库根目录，README 里有每套的页面表：`atom-structure/`、`ion-structure/`、`element/`、`symbols/`、`review/`、`water/`、`purify/`。**新课件优先复用 `purify/`**：它的源文件和构建脚本都在 `purify/src/`，固定规范（字体、工具栏、直接操作、笔记）都已落实。

## 1. 用户是谁、怎么上课

- 初中化学老师，人教版九年级**最新教材**。单元、课题编号以老师给的练习册为准（例如最新教材第四单元：课题 1 水资源及其利用（第 2 课时是水的净化）、课题 2 水的组成、课题 3 物质组成的表示），和老师口头说法不一致时按练习册做，并告诉老师。
- 课件用于**一块教室大屏**，老师操作，全班一起互动；每节课 **45 分钟**，各页 `data-min` 合计必须等于 45。
- 全班分**红队 / 蓝队**对抗，积分贯穿整节课；目录里可以手动加减分。
- 老师习惯发练习册 PDF 说明“题目涵盖范围”，发截图并画红框指出问题。**回复一律用中文**，称呼用“老师”。
- 老师希望你主动给建议，但定下的事就直接做（“开始做吧”）。老师说“按你的理解优化”时，要主动做一轮全课打磨，并说明改了什么。

## 2. 固定规范（每套课件都一样，不随风格变化）

### 内容
- **不超纲**：没学过的概念不提前出现。带中文的化学符号可以提前出现。
- **练习册只定范围和题型，不用原题**（那是学生的家庭作业），不足的部分自己补充。出题见 `references/question-writing.md`。
- **重难点讲解页直接给“笔记”**（关键词荧光笔标出，`→` 写结论），底部加一条“易错”提示；不要只在小结页出现。
- 数据和表述以教材为准；拿不准的数字不编，用教材原话或请老师确认。

### 答题与计分
- **凡是计分的作答，都先作答、再点“提交”判对错**：错了不加分，同时给出正确答案和理由。不要用“拦截错误”“错了抖一下再试”的方式，那样学生怎么做都对。
- 有顺序的知识要**检查顺序**（电子由内向外排、净水器自下而上装填）。
- **找茬、点选类题目按区域判定**：一整片出错的地方（例如液面高于滤纸边缘的一整圈）点哪里都算对，点到别处判“这里没错”。
- 计分统一：课中互动 +5，竞赛题 +10，提升题 +20；错误不扣分也不加分；每次判分后自动换队。
- 给老师留**弹性**：任务可选全做或部分做，可计时，可重来。

### 虚拟实验（与答题不同）
- **让错误操作真实地发生，并展示后果**：不加沸石就暴沸，不通冷凝水就收集不到水。不要用拦截代替后果。只有现实中不能做的危险操作（如往热液体里补加沸石）才拦下，并说明原因。
- **实验既能用按钮，也能直接动手**：拖试剂进容器、点酒精灯点火或熄灭、点水龙头通水、点试管振荡、点水池跳站。按钮和直接操作调用同一套函数（`canvasUI`，见 `references/framework.md` 第 7 节）。

### 版式、按钮与字体
- **页面骨架固定**：页眉（栏目标签 + 标题 + 右上“重新开始”）、舞台、右侧面板（作答）和笔记卡。
- **舞台里的操作按钮一律放在舞台底部中间的工具栏**（`.ctlbar`）：只写文字，不加图标、序号，最多一个主按钮，用过的按钮变灰。作答用的“提交 / 重做”放在右侧面板。
- **全课只用两种字体**：标题、手写标注、画布说明用站酷快乐体（ZCOOL KuaiLe）；正文、按钮、数字用思源黑体（Noto Sans SC）。站酷快乐体的“0”像方块，所以数字用思源黑体。字体按用字裁剪后内嵌，断网也一致。**风格差异靠配色、质感和装饰体现，不靠换字体。**
- **固定画布 + 整体等比缩放**：老师会在约 1000 px 宽的预览窗格和教室大屏上看，布局必须一致。
- 版式整洁：网格对齐，留白一致，文字不截断，标签不互相遮挡、不跑出画面，不留大片空白。

### 画面与科学正确
- **实验装置照教材插图画**：画之前先找最新教材的插图，或请老师发图；画完后逐个核对空间关系（见 `references/lab-apparatus.md`）。
- **动画的位置和因果要对**：加药装置画在它作用的池子上方；先滴入、再扩散、后出现结果；清单在结果出现后才划掉。
- **颜色不能带来科学误导**：例如馏出液是无色的，不能用绿色区分，靠文字标注说明；图例必须与示意图同色同形。
- **微观粒子、杂质要画得形象、数得清**：杆菌带鞭毛，泥沙是带明暗的不规则颗粒；可溶性杂质（色素、异味分子、钙镁离子）也要可视化，全课画法一致。
- 物理逻辑正确：冰浮在水上；装溶液的容器要画出液体；按真实比例呈现，需要看细节时用放大镜或镜头推近。
- 图标用代码绘制、风格统一（几何取自 Material Design Icons），老师不喜欢 3D 表情包式图标。官方标志必须与原图一致，查不到就请老师发图。
- **默认不做 3D**：只有老师主动要求时才做，而且必须用 Blender 建模（见 `references/3d-playbook.md`）。

## 3. 由老师选择的部分与每套要换新的部分

- **视觉风格由老师选**，不必每套都换。规划时列出 3～4 个风格选项（包括用过的、老师满意的，例如浅色贴纸风；也包括没用过的），每个用一句话说明配色、质感和适合的内容，再给出推荐；老师选哪个就用哪个。老师没指定时，先问要不要沿用上一套的风格。以老师最后的指定为准（老师曾先说“元素课件的风格”，随即改为“元素符号课件的风格”）。
- **最终竞赛玩法、课堂小游戏、“哇”时刻每套换新**，避免学生审美疲劳（老师说过“避免连续几期课件的活动、呈现形式等都相似”）。用 `references/catalog.md` 挑选，用 `references/style-history.md` 查重；Boss 等角色形象绝不跨课复用。如果老师想自己选玩法，同样给选项。

## 4. 工作流程

1. **读范围**：读 PDF 和截图，列出知识点、题型，以及练习册没覆盖的必要内容；核对单元、课题编号。
2. **规划并提问**：按 45 分钟排 8–15 页，每页写清“讲什么、学生做什么、怎么计分”，重难点页标出笔记。动手前给老师选项：风格 3～4 个（含用过的）供老师选，竞赛和亮点演示给“推荐 + 1～2 个备选”；同时把拿不准的教学安排问清楚（例如演示实验由谁做、讲多深、要不要记录单）。
3. **找插图**：有实验装置、流程图的页面，先找最新教材插图或请老师发图，确定仪器的空间关系。
4. **搭框架**：复制 `scripts/build_2d_template.py` 到 `<课件>/src/build.py`，源文件放在 `<课件>/src/`（**要提交进仓库**，下次会话才能继续改）。复用 `assets/` 里的固定画布、图标、实验仪器绘图库。
5. **做页面**：按 `references/framework.md` 的骨架和交互模式做；实验按 `references/lab-apparatus.md`。
6. **自检**（不能省）：按 `references/qa-and-publish.md` 跑多分辨率排版审计、逐页截图、模拟真实拖动和点击、检查控制台报错，再拿第 5 节的红线逐条对照截图，像一个挑剔的老师那样找问题。
7. **交付**：提交并推送；README 追加页面表；发布 Artifact（同一文件路径重发，链接不变）；用中文回复，先给链接，再按老师的编号逐条说明，附页面表和需要老师确认的地方。
8. **迭代**：老师指出一个问题时，修根因，并**系统排查全课的同类问题**；把新教训写进 `references/preferences-and-feedback.md`，必要时更新本文件第 2 节。

## 5. 质量红线（交付前逐条确认）

- 六种分辨率（1000×650 到 2560×1080）下所有页面无滚动、无截断、无重叠；控制台零报错。
- 每个按钮都真的点过，每个可拖动的仪器都用模拟拖动测过；直接操作和按钮的结果一致。
- 判分正确：提交前不判，错了不加分，顺序检查生效，找茬按区域判定；每题有解析；`data-min` 合计 45。
- 题干提到的图都真的有、能显示。
- 实验装置的空间关系逐项核对过（谁放在谁上面、谁贴着谁、谁伸进谁里面）；动画方向和先后顺序正确（例如冷凝水下进上出）。
- 颜色、图例、单位与示意图一致，没有误导性的颜色；化学式上下标正确。
- 全课只有两种字体；舞台操作按钮都在底部工具栏，纯文字。
- 3D（如有）：模型贴地、无闪烁、光晕不被裁切、标签不出画面。
- README 已更新，源文件已提交，链接可打开。
