# 互动课件制作（经验沉淀）

这份技能来自与一位初中化学老师的长期合作：已交付 6 套课件（原子结构、原子结构示意图与离子、元素、元素符号与周期表、第三单元复习、水资源及其利用），并经历了几十轮截图反馈。下面把她的偏好、被纠正过的错误和技术经验沉淀下来，让下一套课件一次做到位。

所有已完成课件都在本仓库根目录（`atom-structure/`、`ion-structure/`、`element/`、`symbols/`、`review/`、`water/`），README 里有每套的页面表。新课件优先复用它们的框架代码，而不是从零写。

## 1. 用户是谁、怎么上课

- 初中化学老师，人教版九年级**最新教材**（单元编号以她给的练习册为准，例如“水资源及其利用”在第四单元“自然界的水”）。
- 课件用于**一块教室大屏**，老师操作、全班一起互动；每节课 **45 分钟**（页面 `data-min` 合计要等于 45）。
- 全班分**红队 / 蓝队**对抗，积分贯穿整节课；需要能在目录里手动加减分。
- 她习惯发练习册 PDF 说明“题目涵盖范围”，发截图并画红框指出问题。回复一律用中文。
- 她会在课后根据实际效果再提意见；她希望你主动给建议，但定下的事就直接做（“开始做吧”）。

## 2. 硬性偏好（每次都要满足）

内容与教学：
- **不超纲**：没学过的概念不提前出现（例如原子结构课把相对原子质量放到后面讲）。配有中文的化学符号可以提前出现，帮助学生熟悉。
- **参考练习册的范围，但不要用练习册原题**——那是学生的家庭作业。按“同样的题型”另外出题，不足的部分自己补充。
- **重难点讲解页要直接给出“笔记”**（关键词高亮，学生边听边抄），不要只在小结页出现。
- 数据和表述以教材为准（见 `references/question-writing.md` 的事实清单），拿不准时宁可用教材原话。

互动与游戏：
- **先作答、再点“提交 / 检查”判对错**；错了不加分，并给出正确答案和理由。不要用“拦截错误操作”的方式，那会让学生怎么做都对。
- 有操作顺序的知识要**检查顺序**（例如核外电子必须由内向外排）。
- 给老师留**弹性**：任务可选“全做或部分做”，可计时，可重来。
- 每套课件的活动形式、最终竞赛玩法、视觉风格都要和上一套**明显不同**，避免审美疲劳。用过的形式见 `references/style-history.md`。

视觉与呈现：
- **版式整洁**：统一网格，对齐、等高、留白一致；文字不能被截断，标签不能互相遮挡或跑出画面。
- **配色要高级**，不只是“符合主题”。
- **动效要真实、特效要炫酷**，但要服务于教学（例如真实的水波、液面、滴落、溅起的水花）。
- **图标自己用代码设计、风格统一**；她不喜欢 3D 表情包式的图标。标志类（节水标志、垃圾分类、安全标志）必须与官方图样一致——先查资料核对；如果查不到原图，请她发图，按原图描画。
- **场景演示最好用可交互的 3D 模型**（拖动旋转、缩放、点击）；难做的模型直接用免费 3D 模型库，质量要过关（她批评过粗糙的“猪”和“水龙头”）。
- **按真实比例呈现**，需要看细节时用镜头推近聚焦，让学生直观感受数量差距。
- **物理 / 化学逻辑必须正确**：冰浮在水上、溶液要画出液体、图例颜色与示意图一致、装置逼真、粒子模型能数清质子数。
- **屏幕适配**：她会在不同大小的窗口里看课件（包括约 1000 px 宽的预览窗格）。用“固定画布 + 整体等比缩放”，保证任何屏幕上布局一致。

## 3. 工作流程

1. **读范围**：读 PDF / 截图，列出知识点、题型和练习册没覆盖到的必要内容。核对单元编号和教材版本。
2. **规划**：按 45 分钟排 8–15 页。每页写清楚“讲什么 + 学生做什么 + 怎么计分”。重难点页标出“笔记”。打开 `references/catalog.md`（风格库、竞赛玩法库、小游戏库、互动方式库）和 `references/style-history.md`，挑出最近没用过的组合；动手前用几行字给老师“推荐方案 + 1～2 个备选”（风格、最终竞赛、亮点演示）。她点名的风格优先；她说“开始做吧”就按推荐方案做。
3. **搭框架**：复用翻页 / 积分 / 音效 / 特效框架和固定画布缩放（`references/framework.md`）。用构建脚本把共享代码和本课的 CSS、HTML、JS 拼成单个 HTML 文件，所有素材内联，断网可用。
4. **做页面**：交互页面参考 `references/framework.md` 里的模式；3D 场景按 `references/3d-playbook.md`；图标和模型素材按 `references/assets-and-licenses.md`。
5. **自检**（不能省）：按 `references/qa-and-publish.md` 跑排版审计（多种分辨率）、逐页交互截图、控制台报错检查，再用第 2 节的偏好清单逐条对照截图，像一个挑剔的老师那样找问题。
6. **交付**：提交并推送到指定分支；README 追加页面表；发布 Artifact（同一文件路径重发以保持链接不变）；用中文回复，附页面表，说明做了哪些判断、哪些地方需要她确认。
7. **迭代**：她指出一个问题时，修根因，并**系统性排查同类问题**（她明确要求过“系统性梳理整个课件，排查所有问题”）。

## 4. 质量红线（交付前逐条确认）

- 所有页面在 1000×650、1024×768、1280×720、1366×768、1920×1080、2560×1080 下无滚动、无截断、无重叠。
- 控制台零报错（包括 WebGL 场景）；所有按钮都真正点过一遍。
- 每题都有解析；判分逻辑正确（交卷前不判分、错误不加分、顺序检查生效）。
- 题干里提到的图都真的有（她抓过“这题没有图”“题干说‘该原子’却看不到”）。
- 颜色、图例、单位与示意图一致；化学式上下标正确。
- 3D：模型落地不悬空、没有闪烁的重叠面、光晕完整不被裁切、标签不出画面、物理过程合理。
- `data-min` 合计 45；README 已更新；链接可打开。

## 5. 参考文件（按需读取）

- `references/preferences-and-feedback.md`：逐套课件的需求与被纠正记录（最有价值，动手前读一遍）。
- `references/catalog.md`：常用视觉风格、最终竞赛玩法、课堂小游戏、互动方式、“哇”时刻，每项都注明是否已用过。规划新课件时用来给老师提供参考。
- `references/framework.md`：单文件课件框架（翻页、积分、音效、特效、固定画布缩放、构建脚本），以及常用交互模式与代码坑。
- `references/3d-playbook.md`：three.js 场景的做法：共享渲染器、轨道控制、标签、玻璃 / 水 / 金属材质、地形沙盘、真实比例与镜头编排，以及细节打磨清单。
- `references/assets-and-licenses.md`：本环境能访问哪些素材源（只有 GitHub 和 npm）、已验证的免费模型 / 贴图 / 图标、授权与署名。
- `references/qa-and-publish.md`：Playwright 审计与截图脚本、无头浏览器 WebGL 参数、发布与提交流程。
- `references/style-history.md`：6 套已交付课件各自的风格、互动、竞赛和评价，以及得出的结论。
- `references/question-writing.md`：出题规范、题型、事实数据清单。
- `scripts/`：`audit_layout.js`（多分辨率排版审计）、`shoot_pages.js`（逐页截图）、`strip_for_artifact.sh`（发布前处理）、`three-bundle/`（打包 three.js 与加载器）、`convert_glb.mjs`（解压 Draco 模型并转成 GLB）、`build_template.py`（单文件构建示例）。
- `assets/`：可直接复用的 `fit.js`（固定画布缩放）、`engine3d.js`（3D 引擎层）、`icons.js`（Material Design Icons 图形 + 课件配色的图标系统）。
